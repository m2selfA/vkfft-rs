# VkFFT -> Rust porting plan

## Baseline

- Upstream: `DTolm/VkFFT`
- Version reported by `VkFFTGetVersion()`: 1.3.4
- Baseline commit: `066a17c17068c0f11c9298d848c2976c71fad1c1`
- License: MIT

The paper and upstream implementation both organize VkFFT around three layers: Application, Plan, and Code Generation. The Rust port follows that architecture instead of exposing the original C configuration struct through bindings.

## Source-to-module mapping

| Upstream area | Responsibility | Rust destination |
| --- | --- | --- |
| `vkFFT_Structs` | configuration, plans, axes, specialization constants | `config`, typed plan/kernel IR |
| `vkFFT_AppManagement` | initialization, update, dispatch, cleanup, binary cache | `application` + backend ownership |
| `vkFFT_PlanManagement/vkFFT_Scheduler.h` | algorithm selection, radix/Rader/Bluestein scheduling, upload splitting | `planner` |
| `vkFFT_ManageLUT.h` | twiddle/Rader/Bluestein LUT generation | `lut` |
| `vkFFT_CodeGen/vkFFT_KernelsLevel2` | full kernel structure | high-level kernel IR |
| `vkFFT_CodeGen/vkFFT_KernelsLevel1` | FFT/rader/pre/post routines | reusable kernel IR operations |
| `vkFFT_CodeGen/vkFFT_KernelsLevel0` | math, memory, API-specific syntax | backend lowering |
| `vkFFT_API_handles` | buffer binding, compilation, launch | backend adapters |

## Algorithm parity targets

### Core FFT

- Stockham autosort with radix decomposition over 2/3/5/7/11/13.
- Merged radix kernels (4, 6, 8, 9, 10, 12, 14, 15, 16, 32).
- FFT-convolution Rader for primes whose `p - 1` recursively decomposes into supported small factors.
- Direct Rader for the small-prime range selected by the device profile.
- Bluestein for remaining lengths, with performance-tuned padding selection.
- Four-step FFT for axes too large for one on-chip upload.

### Transform families

- C2C forward/inverse.
- R2C/C2R with Hermitian packing and even-length half-size optimization.
- DCT I/II/III/IV.
- DST I/II/III/IV present in current upstream sources.
- F16 storage/F32 compute, F32, F64, F64-compute/F32-storage, and double-double modes.

### Memory/performance features

- Coalesced grouped uploads for non-unit-stride axes instead of mandatory standalone transposes.
- Shared-memory bank-conflict avoidance and padding.
- Register-resident large transforms and register-boost selection.
- Four-step reorder fusion.
- Broader recursive/nested convolution fusion and native zero padding.
- LUT/on-the-fly twiddle selection.
- Kernel/binary caching.

## Milestones

### M1 — planner + numerical oracle (implemented)

- Public Rust configuration types.
- Stockham/Rader/Bluestein classification.
- Rader primitive roots and radix plans.
- Portable Bluestein smooth-size selection plus fixed-device auto-padding in the M2 planner.
- CPU reference C2C FFT for generated-kernel validation.

Low-level `FftPlan::build` intentionally keeps a deterministic portable Bluestein picker: the smallest 2/3/5/7-smooth size at or above `2N-1`. Device-scored planning now consumes the fixed-commit `initializeBluesteinAutoPadding` tables first and falls through to the upstream power-of-two/smooth `isGoodSequence` search with the real batch/RHS estimate; execution therefore no longer substitutes portable padding for a known GPU profile.
